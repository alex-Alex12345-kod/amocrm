# FLOWBIT Dedupe Lab

Серверный прототип внешней интеграции amoCRM. Это не приватная интеграция и не завершенный виджет автосклейки.

Тестовый аккаунт: glxxb2xd21.amocrm.ru (33360434).

## Реализовано

- Кнопка OAuth с метаданными для создания внешней интеграции; прием client_id/client_secret по вебхуку, обмен кода, обновление токенов.
- AES-GCM шифрование данных OAuth в R2; серверные секреты в переменных окружения.
- Проверка state и cookie; отказ при попытке подключить аккаунт, отличный от тестового.
- Чтение сделок и контактов через API v4; ограничение выбранной воронкой.
- Нормализация телефонов с явным международным форматом и префиксом 8/7 для +7; неоднозначные короткие номера пропускаются.
- Поиск прямых пар совпадений по телефону, email и явно указанному ID поля Instagram.
- Только отчет, без объединения, удаления или изменения карточек.
- API защищен LAB_SERVICE_KEY или заранее закрепленной идентичностью владельца ChatGPT.

## Переменные окружения

- VAULT_KEY: 32 байта в Base64; секрет.
- LAB_SERVICE_KEY: случайный ключ серверного доступа; секрет.
- INSTALL_ENABLED: 1 для временного открытия регистрации OAuth.
- ALLOW_OWNER_BOOTSTRAP: только 1 при первоначальной привязке владельца на приватном сайте. При публичном доступе должен быть 0.

## Следующие обязательные проверки

1. Разместить Node-сервис на доступном VPS с HTTPS и разрешенными входящими POST. Разрешение пользователя на OAuth уже получено; повторно запрашивать его без изменения области доступа не нужно.
2. Предоставить интеграции доступ к данным только тестового аккаунта через amoCRM.
3. Убедиться в интерфейсе amoCRM, что создан тип «Внешняя».
4. Проверить чтение и поиск на созданных дублях через полученный OAuth access_token.
5. Отдельно исследовать доступность серверного объединения существующих сделок/контактов. Не подменять склейку закрытием сделки, перепривязкой контакта или копированием полей.
6. Добавить различающиеся примечания и задачи, проверить их сохранность; чаты и звонки требуют отдельного воспроизводимого тестового источника. Не заявлять проверку переписок без реальных сообщений.
7. Проверить повторный запуск, конфликт полей, разные заказы одного клиента, сделки за пределами выбранной воронки.

## Ограничения прототипа

- Автосклейка не реализована: доступный внешней интеграции механизм еще не подтвержден.
- Нет фоновой очереди, автоматической подписки на события, механизма отката и производственного мониторинга.
- Нужны блокировки для конкурентного обновления токенов/обработки повторных OAuth callbacks перед промышленным использованием.
- Ограничение чтения: 5000 записей каждой сущности; при превышении возвращается ошибка, а не неполный отчет.
- Поле Instagram сравнивается как строка. Его происхождение, вид идентификатора и область уникальности должен подтвердить реальный коннектор клиента.
- Временная почта не подходит для долгосрочного владения продуктивным аккаунтом.

## Альтернативное размещение на VPS

`server.mjs` адаптирует те же обработчики к Node.js 22, хранит зашифрованные записи на диске и удаляет недоверенные заголовки идентичности ChatGPT. В комплекте Dockerfile, compose.yaml и Caddyfile для HTTPS.

Необходимы сервер, домен с A/AAAA-записью на этот сервер, открытые порты 80/443. Скопировать .env.example в .env, задать LAB_DOMAIN/PUBLIC_ORIGIN и случайные VAULT_KEY/LAB_SERVICE_KEY. Никогда не переносить секреты в репозиторий.

Команды генерации значений (выполнять на целевом сервере):

```sh
openssl rand -base64 32
openssl rand -hex 32
docker compose up -d --build
```

Далее открыть /begin в браузере, где выполнен вход в тестовый amoCRM. /health и /api/* доступны только с Authorization: Bearer LAB_SERVICE_KEY. Новое размещение требует повторного OAuth, так как Redirect URI изменится.

Проверено: локальный HTTP-адаптер, сохранение записей, контроль доступа, обработчики OAuth на синтетических данных. Docker-сборка, выпуск сертификата, публичный VPS, реальная авторизация и сохранность истории при слиянии не проверены.

## Подготовка Render Free

Добавлен render.yaml: Node.js 22, plan: free, HTTPS-адрес берется из RENDER_EXTERNAL_URL, health check /ready, без платной базы данных и диска. Ресурсы еще НЕ созданы на Render. Для создания нужно подключенное приложение Render либо вход в аккаунт провайдера.

Хранилище /tmp/flowbit-dedupe-lab временное: после сна, перезапуска и нового развертывания OAuth может потребоваться повторно. Бесплатный сервис засыпает после 15 минут без входящего трафика; перед выдачей доступа amoCRM нужно открыть корневую страницу и дождаться запуска. Для текущей короткой проверки это допустимо, для клиентского продукта — нет.

Секрет VAULT_KEY должен содержать 32 случайных байта в Base64. LAB_SERVICE_KEY генерируется как отдельный случайный секрет. Не использовать generateValue для VAULT_KEY без проверки формата/длины: произвольная строка не является ключом AES-256 в Base64.

Платные тарифы, платные диски и добавление способа оплаты не разрешены и для этой проверки не нужны.

Документация: https://render.com/docs/free , https://render.com/docs/blueprint-spec , https://render.com/docs/environment-variables
